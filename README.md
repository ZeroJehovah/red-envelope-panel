# 红包口令面板（浏览器扩展）

把 [scripts](https://github.com/ZeroJehovah/scripts) 仓库中的 `linuxdo-hongbao-code-sidebar.user.js`（原先挂在论坛侧边栏上的红包口令脚本）改造成 Chrome 扩展：在扩展图标弹出面板里提交 hb.unsnow.org 口令，或把面板固定在浏览器侧边栏常显。

面板运行在浏览器层，**与浏览的网站无关**：不需要在论坛页面注入任何东西，刷任何网站时都能随时打开提交口令、查看领取结果。

## 当前状态

- 里程碑 1（仓库与骨架，v0.2.0）：清单、后台状态层、弹出面板、常显侧边栏外壳、图标与静态自检。
- 里程碑 4 的输入与清洗（v0.3.0）：口令输入区（单个/批量、文本/数字开关、字数提示与「拆红包」按钮）、输入与粘贴即时清洗、分享文案自动取出口令、开关设置经后台持久化。
- 里程碑 2 + 3 + 领取链路（v0.4.0）：提交进入后台队列，按 5 秒基础间隔（可加时）逐条查询，请求一律由后台发出；命中红包后「协议」模式直接领取，「古法」模式停在「待开启」等你在历史行里点「开红包」；领取结果、失败与未确认提示写回历史，失败会暂停队列并可手动继续；历史支持作废、删除、清空与全部作废，删除按 ID 墓碑跨面板生效。面板另有「检查登录」按钮用于确认红包站登录态。
- 写请求来源 + 抽奖（v0.5.0）：红包站的写接口（领取、抽奖报名）只接受它自己的来源，扩展发出的请求会被回 403「请求来源不合法」，现在由清单里的声明式规则（`rules.json`）改写 `Origin`/`Referer` 修掉。限时抽奖按自己的流程走：古法在历史行点「参与抽选」，协议模式自动报名，报名后停在「已参与抽选，等待开奖」，后台看护按服务器的 `draw_at` 轮询到开奖并把中奖/未中结果写回同一行；看护只读、与查询共用同一份限速节奏，worker 被回收后重新查询口令即可自动接上。
- 红包详情卡片（v0.6.0）：历史行上的「开红包」／「参与抽选」／「查看」会在面板里展开一张信封卡片（不注入网页），显示金额、领取进度与领取记录；限时抽奖另显倒计时、参与名单与中奖公示，卡片打开时按 4 秒节奏刷新。领取与报名仍然只认卡片上由真实用户点击触发的按钮，一次点击只放行一次请求。
- 面板 1:1 复刻脚本版侧边栏（v0.7.0）：脚本版的悬浮窗口改成点扩展图标弹出、停靠列改成浏览器常显侧边栏，面板里的结构与脚本版逐项对齐——头部两个开关（单个/批量、文本/数字）与打开红包站/配置/收起三个图标按钮，齿轮里是可折叠的设置（领取方式、间隔时间、显示方式、版本号），输入框与批量文本域、「拆红包」与字数提示，暂停时的「恢复执行」横幅，「口令历史（N 条 · 排队 M 条）」与作废队列/清空历史，逐行的时间、数字标记、点击口令自动填入输入框、红包详情入口与作废/删除。
- 红包卡片按原尺寸显示 + 修掉关卡片后面板点不动（v0.8.0）：卡片尺寸回到原站设定——320×520 再乘原站的 1.2 倍缩放（显示 384×624，抽奖卡 420×640 显示 504×768），不再为了塞进面板而拉伸，也不再在窄屏/矮屏上二次缩小；窗口不够大就加大窗口：弹出面板宽度 560px、高度顶到浏览器上限 600px（常显侧边栏里卡片按完整的 384×624 显示）。另修复一个 bug：卡片宿主是固定定位、盖住整个面板的一层，关掉卡片后没撤掉，留在 DOM 里会把面板的点击整个吞掉（表现为关掉红包后面板点不动、重开面板才恢复），现在关闭时连宿主一起撤掉，并让宿主在无卡片时不吃指针事件。

- 删掉面板底部提示行（v0.8.1 先去掉常驻说明文案，v0.8.2 整行删除）：脚本版侧边栏没有这一块，面板也不再留。结果与错误改走脚本版本来就有的出口——领取/参与/查询写在历史行里，空草稿与非法口令由「拆红包」按钮自身拦截（禁用 + 提示气泡），队列出错走「执行已暂停」横幅，「检查登录」的结果写在配置面板「红包站：」那一行；其余没有行级出口的问题只记控制台。

- 面板高度跟着内容走、空历史照脚本版留白（v0.9.0）：弹出面板不再固定 600px 高，平时只占内容那么多（空历史实测 172px），多出来的高度让给口令历史，历史长了列表自己滚动；红包卡片打开时面板才撑到浏览器上限（600px）把原尺寸卡片铺开，关掉卡片立刻收回，平时不再留一块空底。同时按脚本版删掉空历史的占位文案「队列为空，输入口令后点「拆红包」。」（脚本版空列表就空着）。

- 去掉开卡闪烁、停靠/悬浮跟实际形态对齐（v0.9.1）：卡片样式原来是放进 shadow root 的 `<link>`，样式到达之前会先画一帧没样式的卡片——暗色主题下就是「底部关闭按钮先亮一下再变暗」。现在面板一加载就把随包的 `envelope.css` 读成一张 stylesheet，开卡片时同步挂上，读不到时才退回 `<link>` 并在这期间先藏住卡片。「显示方式」也不再只是记个偏好：进到侧边栏就记成「停靠」，侧边栏收起或被浏览器藏起来时自动切回「悬浮」，在侧边栏里点「悬浮」会顺手把自己收起来。

- 换成红包字形图标（v0.9.3–v0.9.5）：扩展图标不再用另画的一枚「红包封口」，直接沿用口令历史里「查看红包详情」按钮那颗红包字形（与脚本版网站行内按钮同一组 path），透明底，由 `tools/make-icons.py` 光栅化成 16/32/48/128。v0.9.4 补回中间那枚金色封口：插件 v0.7.0 复刻时把它换成了 `hb-packet-seal` 这个 class 却没补样式，历史行那颗图标一度整颗是红的。v0.9.5 把颜色对齐脚本版：这枚字形是站点品牌图形，历史行与扩展图标都改用脚本版写死的站点色——主体 `#dc2626`（悬停 `#b91c1c`）、封口盘 `#eab308`（即脚本版的 `fill="#eab308"`、「主体红色且中间圆点金色」），不再套面板的莫兰迪红金 `#c05c5c` / `#c98f4b`（那个红在同样是红的背景下明显更淡）。

- 红包详情改用独立小窗口（v0.9.7）：卡片不再挤进面板——弹出面板顶到浏览器上限也只有 600px 高，原尺寸的卡片（普通 384×624、抽奖 504×768）进去就会被压扁。现在点历史行的「开红包／参与抽选／查看」会开一个扩展自己的小窗口（`card.html` + `card.js`，`type: 'popup'`，没有标签栏与地址栏），窗口里只有那一张卡片：先按卡片尺寸开，再用窗口自己量到的边框差值收紧一次。同时只留一个详情窗口——窗口号记在 `chrome.storage.session`，同一个红包就把它拉到前面，换个红包就把旧窗口关掉、按新卡片重开一个，不会点一次开一个；窗口关掉或那条记录在面板里被删掉时自动收尾。面板因此也不再需要 v0.9.0 那套「卡片打开时给 body 打 `hb-card-open` 把窗口撑到 600px」，面板宽度当时仍留在 560px（v0.9.11 收窄到 400px）。

- 面板配色换成脚本版那套 + 弹窗收窄（v0.9.8–v0.9.11）：卡片文案与配图按原站 `app.js` 逐句对齐、清单 CSP 放行站点头像（`img-src` 补 `https:`，v0.9.9）；卡片不再自带焦点圈（去掉打开时的 `focus()`）、「确定」按钮删掉我们自加的高度回到原站尺寸（v0.9.10）；面板配色从莫兰迪色系整体换成脚本版（linux.do）那套调色板并按 `prefers-color-scheme` 分亮暗两套，弹出面板宽度从 560px 收到 400px（卡片早已在独立窗口里，面板不需要那个宽度了，v0.9.11）。

- 详情窗口先铺 loading、数据回来才铺卡片（v0.9.12）：详情读取本身要占一次请求间隔（刻度按「上一次请求结束」起算 5 秒 + 加时），点开时刚查询或刚领取完，卡片就会几秒不变。现在窗口打开后先只问后台内存（`hb:packet` 带 `cache: true`，一次请求都不发）——命中就直接铺卡片，等于把那次等待整个省掉；内存里没有（worker 被回收过）就先只显示一层简洁的 loading（小转圈加「正在读取红包详情…」，亮暗两套），等只读查询回来再铺卡片，期间窗口里没有任何红包样式。已经在看结论的卡片（领取记录、参与名单）铺上之后仍在后台补一次只读刷新，还在等点击的卡片不补——免得跟用户紧接着的那一次点击抢同一份请求间隔。

- 停靠/悬浮成为持久选择，打开面板就把焦点放进输入框（v0.10.0）：配置面板里的「显示方式」不再只是当前形态的镜像，而是用户的持久选择——**停靠**时点扩展图标交给浏览器开合侧边栏（后台把 popup 清空，图标点击才不会被弹窗截走），**悬浮**时点图标弹出面板；手动把侧边栏关掉不改这个选择，下次点图标仍然只开侧边栏。另外弹出面板与常显侧边栏一打开就把焦点放进输入框（单个模式是单行输入框、批量模式是文本域），已经在别的控件上编辑时不抢。
- 侧边栏也能自动聚焦输入框了（v0.10.1）：侧边栏的交焦点比页面加载晚（Chrome 把面板挂进窗口右侧之后才把焦点交过去，还可能先落在面板里别的元素上），原来只放一次经常落空；现在挂载后补几次、面板重新露出来与窗口拿到焦点时再各补一次，只有你真的动过键盘鼠标才不再插手。

- 古法自动弹出领取卡片、历史按钮按需开卡、限速收窄（v0.11.0）：古法口令查到可领的红包后，后台会自己开一张**领取卡片**（`card.html?view=claim`）——脚本版 `showClaimEnvelope` / `showLotteryEnvelope` 的对应物，领取只认那张卡片上的真实点击；点历史行的红包按钮开的是**只读详情卡片**（`view=detail`），两张卡片各占一个窗口、互不顶掉。同时把限速收窄到只管口令查询（按 id 的只读——开奖看护轮询、详情读取、`/api/me`——既不等间隔也不刷新刻度），并让领取成功后固定补一次只读重读，领取记录里才会出现自己那一行。

- 唤醒不再重查「待开启」口令（v0.11.1）：service worker 被回收再唤醒是几十秒一次的常态，而它此前按脚本版「页面重载」的语义处理待开启条目——每次唤醒都替用户重跑一遍那条口令，把限速刻度顶到「刚刚」（于是闲置很久后提交的口令仍显示「排队中」），古法路径上还会把领取卡片重弹一遍（表现为「卡片当场弹出来、过了间隔又弹一次」）。现在带红包快照的待开启条目唤醒后原地待着，已报名未开奖的抽奖把收摊时刻落库、唤醒时直接装回看护；领取卡片被关掉后要回到它，点历史行即可（「待开启 + 古法」的历史行开的就是那张领取卡片）。

- 领取方式增加「动态」（v0.12.0）：设置里的领取方式从「古法／协议」两段扩成三段——选**动态**时下方多出一行「领取阈值：自动协议领取[总额／人均]达到 <input> 的红包」，输入框收非负数、最多两位小数（默认 `0`）。判定落在口令查到红包**之后**（总额／人均只有站点应答里才有），新发现的红包该指标**大于等于**阈值就走协议自动领取，否则转古法弹领取卡片；指标算不出来（红包没有总额，或按人均而红包没有份数）按未达标处理，转古法。判定读的是**领取这一刻**的设置，排队中的口令跟着最新阈值走、不用重新提交；条目一旦判定就把结果固定成 `manual`／`direct`（不再留 `dynamic`），结果行另写一句 `动态：人均 2.00 LDC ≥ 阈值 2.00，自动协议领取` 说明这次的走法。

- 领取的 POST 不再等口令查询的间隔（v0.12.1）：间隔只给「输入口令」那次查询定，点卡片上的「开」/「参与抽选」当场发出去——此前（v0.9.2 起）古法点「开」也要先等满一个间隔才发 POST，面板行里还写着「正在等待领取间隔…」。现在这一行改成「正在开启红包…」，重复点击照旧被在途标记挡下；刻度此后只有口令查询一个写者，点一次领取也不会把后面排队的口令顶到「刚刚」。
- 刻度落在口令查询结束那一刻（v0.12.2）：间隔只给「输入口令」那次查询定，而刻度的写入点原先在整条操作结束时——协议模式下那条跟在查询后面的领取 POST 有多慢，下一次查询就被推迟多久。现在刻度与脚本版 `sharedQuery` 写在同一处（查询一结束就写），POST 的耗时不算进间隔。

站点内嵌模式与脚本版历史／设置迁移都已评估并放弃（v0.9.6），评估记录见 `docs/开发计划/浏览器插件化.md`。

## 形态

- **弹出面板（显示方式 = 悬浮）**：点扩展图标打开，适合临时提交一两条口令；在任意标签页都能唤出。
- **常显侧边栏（显示方式 = 停靠）**：`chrome.sidePanel`，可固定常显，适合一边浏览一边等待领取结果。
- **红包详情窗口**：点历史行的红包按钮时另开的小窗口，只放一张卡片；不是常驻形态，关掉就没了。

「显示方式」决定点扩展图标做什么：停在**停靠**上，图标点击交给浏览器开合侧边栏（不会再弹面板，手动关掉侧边栏之后还是这样）；切回**悬浮**，图标点击恢复成弹出面板。开关本身就在面板的配置面板里：在弹出面板里点「停靠」会顺手把侧边栏拉起来并收起自己，在侧边栏里点「悬浮」会把自己收起来。

脚本版那套贴在页面右侧的停靠/悬浮形态（「站点内嵌模式」）已评估并放弃：它与点扩展图标、点侧边栏在日常使用上没有区别，代价却是请回站点权限与内容脚本，外加脚本版那串按站点逐个给固定层打补丁的适配（`.d-modal`、`.pswp`、`.reader-mode` 等）。扩展保持零站点权限。

## 安装（开发）

Chrome（Manifest V3，116+）：

1. 打开 `chrome://extensions`
2. 右上角开启「开发者模式」
3. 「加载已解压的扩展程序」→ 选择本目录 `src/`

## 目录

- `manifest.json`（MV3）、`rules.json`（写请求 `Origin` 改写规则）、`background.js`（service worker）、`browser-shim.js`（兼容层）
- `popup.*`（点图标面板）、`sidepanel.*`（常显侧边栏）、`panel.js`／`panel.css`（两者共用的面板渲染：头部开关与设置面板、输入区、队列与历史区）
- `code-rules.js`（口令清洗、分享文案取词与校验，移植自脚本版）
- `hb-protocol.js`（红包站端点、错误文案与结果行，后台与测试共用）
- `envelope.js`／`envelope.css`（红包详情卡片：信封弹窗、领取记录、抽奖倒计时与名单）、`card.html`／`card.css`／`card.js`（放卡片的小窗口）
- `icons/`、`tools/`、`tests/`

约束与设计说明见 `AGENTS.md`，需求与计划见同级 `docs/`。

静态自检：在 `src/` 下执行 `node --test`（清单、口令规则、后台集成）。
面板 DOM 自检：把 `tests/panel-harness.html` 复制到与 `manifest.json` 同级的目录后用 Chrome 打开；详情窗口的自检页是 `tests/card-harness.html`（用 `?id=hp1`、`hp2`、`hp3`、`hp4`、`hp5`、`missing` 各跑一遍，其中 `hp5` 专门验「数据回来之前只显示 loading」）。
